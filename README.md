# Монитор новостей госорганов и информагентств

Проект собирает новости с сайтов российских государственных органов и
информационных агентств, ищет заданные ключевые слова и сохраняет результаты
в SQLite.

Версия 2026.08.17.2 гарантированно закрывает SQLite-соединения после каждой
операции, включая Windows, где открытый файл блокирует удаление временной базы.

## Установка

Рекомендуется Python 3.12 или 3.13.

### Windows

```powershell
py -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
playwright install chromium
```

### macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
playwright install chromium
```

## Запуск

Парсеры работают независимо: госорганы проверяются каждые пять минут,
информагентства — каждые три минуты, а свежие номера газет — при запуске и
затем ежедневно в 08:00 по локальному времени компьютера:

```bash
python main.py
```

Веб-интерфейс запускается отдельно:

```bash
python web_app.py
```

## Развёртывание на сервере

Готовые конфигурации для Ubuntu, systemd, Gunicorn и Nginx находятся в
[`deploy/README.md`](deploy/README.md). Серверный запуск использует две
независимые службы: падение веб-интерфейса не останавливает парсер, а падение
парсера не выключает сайт. Обе службы автоматически восстанавливаются и
запускаются после перезагрузки VPS.

После этого откройте <http://127.0.0.1:5000>.

При первом открытии «Монитор» предложит создать владельца. Первая учётная
запись получает роль администратора; пароль должен содержать не менее 10
символов. После настройки все страницы требуют входа. Пароли сохраняются в
SQLite только в виде защищённых хешей, а изменяющие состояние запросы
проверяются CSRF-токеном.

Ключ пользовательских сессий автоматически создаётся в локальном файле
`.monitor_secret`, который исключён из Git. На сервере вместо файла можно
задать постоянный секрет через переменную окружения `MONITOR_SECRET_KEY`. При
работе через HTTPS также установите `MONITOR_HTTPS=1`, чтобы cookie сессии
передавалась только по защищённому соединению.

При первом запуске существующие `all_news.json` и `found_news.json`
автоматически импортируются в `news.db`. Исходные JSON-файлы не удаляются и
остаются резервным снимком. Все последующие обновления записываются в SQLite.

Проверить базу после миграции:

```bash
python -c "from utils.storage import database_stats; print(database_stats())"
```

Создать согласованную резервную копию работающей базы:

```bash
python -c "from utils.storage import backup_database; print(backup_database())"
```

При запуске `main.py` база автоматически проверяется, после чего в папке
`backups/` создаётся один снимок на каждый календарный день. Хранятся последние
семь снимков; более старые удаляются автоматически. Число копий можно изменить
через `DATABASE_BACKUP_RETENTION` в `config.py`.

Получить расширенный статус SQLite (целостность, размер, режим журнала и
последняя копия):

```bash
python -c "from utils.storage import database_stats; print(database_stats())"
```

Администраторские страницы «Источники» и «Система» автоматически показывают
понятные предупреждения: пустую выдачу, серии ошибок, остановившееся расписание,
долгое отсутствие новых материалов, нарушение целостности SQLite и устаревшую
резервную копию. Пороги различаются для госструктур, информагентств и газет,
поэтому ежедневный график прессы не считается сбоем.

После каждой фактической проверки `main.py` ведёт в SQLite журнал инцидентов.
Пустой ответ или ошибка открывают запись, повторные неудачи увеличивают её
счётчик, а третья подряд повышает уровень до критического. Первая успешная
проверка автоматически закрывает инцидент и фиксирует продолжительность сбоя.
История доступна администратору в разделе «Инциденты» и не требует чтения
технического журнала.

Текст публикации загружается и сохраняется в SQLite только при первом открытии
статьи внутри «Монитора». Повторное открытие использует локальную копию и не
создаёт новый запрос к источнику. Пустые ответы и ошибки не кешируются; кнопка
«Обновить текст» позволяет вручную заменить сохранённую версию. В базу попадает
только очищенный текст без изображений и HTML, не более 100 000 символов на
статью.

Страницы Минсельхоза и Минцифры сначала читаются обычным запросом. Если сайт
отдал только пустой каркас без текста публикации, «Монитор» один раз повторяет
загрузку через браузер и сохраняет полученный результат в SQLite.
Лента Минпромторга использует тот же принцип: быстрый HTML-запрос остаётся
основным, а при пустой JavaScript-разметке первая страница один раз открывается
через Chromium.

В разделе госструктур также подключён официальный Atom-канал сайта Президента
России. Канал отдаёт точные даты, прямые ссылки и для большинства публикаций —
полный текст, поэтому повторно загружать защищённую страницу Кремля не нужно.

Веб-интерфейс разделён на «Госструктуры», «Информагентства» и «Газеты». В каждом разделе
сохраняются прежние функции: общая лента, совпадения, поиск, фильтр источников,
избранное и отметки непрочитанных новостей. Лента разбита на страницы по 20
материалов; поиск по Enter проверяет весь выбранный раздел, а не только текущую
страницу.

В разделе информагентств подключены РИА Новости, открытая официальная
RSS-лента ТАСС, официальные RSS-ленты Интерфакса и 12 источников Yahoo! JAPAN:
восемь тематических RSS, RSS AP, CNN и Teikoku Databank, а также публичная
страница Jiji Press (её отдельная Yahoo RSS больше недоступна).
Yahoo опрашивается раз в 10 минут. Полный текст загружается и кэшируется только
при открытии выбранной карточки; если страница защищена, показывается анонс RSS.
Для ТАСС внутри
«Монитора» показывается официальный анонс, а полный материал открывается
на сайте агентства. Публикации Интерфакса доступны для внутреннего чтения.

В разделе «Газеты» подключены «Независимая газета», «Коммерсантъ»,
«Известия», «Российская газета», «Ведомости», «Красная звезда» и
«Комсомольская правда». НГ
забирается из текущего свежего номера на `ng.ru/gazeta/`. Если страница номера
заблокирована, страница свежего номера сначала читается через Google-представление,
а затем через внешний текстовый шлюз Jina Reader. Так сохраняется полный состав
печатного выпуска. Официальный RSS и
`rss2json` используются только как аварийный резерв; такие карточки отмечаются
«Онлайн НГ · резерв». Для «Коммерсанта» используется официальная
полная RSS-лента газеты, а страница `/daily` определяет текущий выпуск без
вычисления его номера. «Российская газета» читается со страницы свежего номера,
«Ведомости» — из официальной RSS последнего выпуска, «Известия» и «Красная
звезда» использует два официальных RSS: выпусков и отдельных статей.
«Комсомольская правда» загружается из официальной RSS всех разделов, из которой
выбираются публикации самой свежей московской даты. Для сортировки
используется дата публикации самой статьи: она может отличаться от даты
печатного номера.

Газетная группа запускается строго один раз в сутки в 08:00 по локальному
времени компьютера. Для НГ используется особенно бережный режим: один прямой
запрос к свежему номеру, при блокировке — одно чтение Google-представления и
одно чтение той же страницы через Jina Reader. Только если все три страницы
недоступны, проверяются прямой RSS и
его RSS-шлюз. Повторов и браузерного резерва нет. Через шлюзы передаются только
публичные URL НГ, без пользовательских данных и содержимого базы. Если
недоступны все способы, уже сохранённые материалы остаются в SQLite, а
следующая попытка выполняется только на следующий день.

В интерфейсе заголовок открывает текст новости внутри «Монитора», а ссылка на
оригинал остаётся доступна отдельной кнопкой. Статьи НГ внутри «Монитора»
читаются через Google-представление страницы: открытие нескольких материалов
не создаёт серию запросов с локального IP пользователя к `ng.ru`.
Статьи «Российской газеты» также читаются через Google-представление, поскольку
прямой запрос приложения к публичной статье РГ может получить ответ HTTP 401.
В шапке показываются часы Москвы и Токио.
В «Сводке покрытия» перечисляются названия источников с ошибкой или пустой
выдачей, поэтому проблемный сайт можно найти без просмотра консольного лога.
Кнопка «Ключевые слова» позволяет добавлять и удалять фразы и сразу
пересобирает раздел «Совпадения». Пользовательский список сохраняется в
`keywords.json`; до первого изменения используются слова из `config.py`.
Список ключевых слов доступен всем вошедшим пользователям.

Имя пользователя в шапке ведёт в раздел «Мой аккаунт», где можно сменить свой
пароль после подтверждения текущего. Администратору там доступна страница
«Пользователи»: создание аккаунтов, назначение ролей, временная смена пароля и
отключение входа. Аккаунты не удаляются, чтобы связанные с ними личные данные
можно было безопасно сохранить. Приложение не позволит отключить или понизить
последнего активного администратора.

Раздел «Закладки» хранит сохранённые новости отдельно для каждого аккаунта.
Пользователь может создавать собственные папки, перемещать между ними
материалы и оставлять к каждой публикации заметку длиной до 5000 символов.
Удаление папки не удаляет сохранённые статьи: они переходят в «Без папки».
Сердечки, сохранённые старой версией интерфейса в браузере, один раз
автоматически переносятся в SQLite при входе пользователя. После переноса
закладки доступны этому аккаунту с любого устройства, на котором открыт
«Монитор».

Порядок источников в правой панели также является личной настройкой аккаунта.
Кнопка «Изменить» включает перетаскивание источников; после нажатия «Готово»
выбранный порядок сохраняется в SQLite отдельно для госструктур,
информагентств и газет. Новые
источники, которых ещё не было в сохранённом списке, автоматически появляются
в его конце. В компактной шапке и вкладках «Все»/«Совпадения» числовые
счётчики скрыты, а индикатор работоспособности перенесён под имя пользователя.
Кнопка «Ключевые слова» доступна всем вошедшим пользователям; изменения списка
сразу пересобирают общий раздел «Совпадения». Удалена только кнопка «Фильтры».

Администратору доступен отдельный раздел «Источники». В нём показываются
последняя проверка и успешный запуск каждого парсера, дата последнего нового
материала, число публикаций, длительность и последняя ошибка. Оттуда источник
можно поставить на паузу или отправить на внеплановое обновление. Ручная
проверка добавляется в SQLite-очередь и выполняется работающим `main.py`, поэтому
веб-интерфейс не зависает на медленном сайте и не запускает один источник
дважды. Если основной процесс был аварийно остановлен, зависшее задание
автоматически помечается ошибкой при следующем запуске.

В соседнем административном разделе «Система» показываются результат проверки
целостности SQLite, размер базы, количество новостей, совпадений и сохранённых
текстов, список резервных копий и последние строки `parser_errors.log`.
Администратор может создать ручной снимок базы прямо из интерфейса; приложение
оставляет не больше десяти таких копий, чтобы они не заполняли диск. Удаление
копий и очистка журнала из веб-интерфейса намеренно не выполняются.

Раздел «Инциденты» хранит историю пустых ответов и ошибок парсеров, автоматически
закрывая запись после восстановления источника. На странице «Надёжность» эта
история превращается в отчёт за 7 или 30 дней: процент доступности, суммарный
простой, число сбоев и средняя длительность. Процент считается по времени, а не
по количеству ошибок; статистика начинает накапливаться после установки журнала.

## Основные файлы

- `main.py` — запускает все парсеры.
- `config.py` — ключевые слова и интервалы.
- `parsers/sites/` — отдельный модуль для каждого источника.
- `utils/http_client.py` — загрузка обычных HTML/XML-страниц.
- `utils/js_client.py` — загрузка сайтов через Chromium.
- `utils/parser_runner.py` — изолированный запуск источника с жёстким
  ограничением времени; зависший сайт не останавливает общий цикл.
- `utils/storage.py` — SQLite, автоматическая миграция старых JSON и резервное
  копирование базы, учётные записи, хеши паролей, личные папки и закладки.
- `utils/auth.py` — безопасный постоянный ключ пользовательских сессий.
- `utils/news.py` — нормализация URL и удаление дублей.
- `utils/status.py` — сводка работоспособности всех источников.
- `utils/source_groups.py` — разделение источников по разделам интерфейса.
- `web_app.py` — локальный интерфейс.

Ошибки сети и парсеров записываются в `parser_errors.log`.
Последнее состояние источников сохраняется в `parser_status.json`. Настройки
ключевых слов остаются в `keywords.json`.

Веб-интерфейс кэширует уже декодированные ленты в памяти и автоматически
сбрасывает кэш при изменении SQLite/WAL. В пределах одного HTTP-запроса каждая
лента читается только один раз, а индекс непрочитанных ограничен последними
2000 материалами раздела. Это ускоряет переходы между страницами без задержки
обновлений парсера и без изменения данных в базе.

Для нестабильных ночных источников действуют отдельные предохранители:
Сахалин прерывается через 90 секунд, Киодо — через 45 секунд. Киодо объединяет
общую ленту с разделами «Общество», «Политика», «Экономика», «Спорт» и
«Культура», а после полностью пустых попыток постепенно увеличивает интервал
до часа. «Российская газета»
при недоступности страницы свежего номера использует официальный XML-анонс.
В диагностике краткий сбой в течение суток после успешного запуска отмечается
как временный, а длительная недоступность — отдельно.

## Ночной замер памяти

Для проверки расхода RAM запускайте не `main.py`, а диагностическую оболочку:

```powershell
python .\scripts\night_monitor.py
```

Она запускает обычный парсер и каждые 10 секунд измеряет всё дерево процессов,
включая Playwright/Chromium. Остановка — `Ctrl+C`. Результат сохраняется в
новой папке `night_runs\дата_время`:

- `memory.csv` — все замеры RAM, CPU, числа процессов и размера базы;
- `parser.log` — полный вывод парсера;
- `summary.json` — длительность, пик и изменение памяти за запуск.

Можно автоматически завершить тест через заданное число часов:

```powershell
python .\scripts\night_monitor.py --hours 10
```

Папку конкретного запуска можно упаковать в ZIP для анализа. Сам каталог
`night_runs` исключён из Git.

Любую группу можно обновить вручную, не дожидаясь расписания:

```powershell
python main.py --once newspapers
python main.py --once kyodo
python main.py --once agencies
python main.py --once government
```

Команда `python main.py --once all` последовательно обновляет все группы.
# Отдельный VPN-маршрут для Киодо

Лента и статьи `47news.jp` могут работать через SOCKS5-сервис на личном
сервере Amnezia. Остальные источники при этом продолжают использовать
обычное подключение.

1. Установите зависимости: `python -m pip install -r requirements.txt`.
2. Скопируйте `.env.example` в `.env`.
3. Запишите выданные Amnezia адрес, порт, имя пользователя и пароль:

```env
KYODO_PROXY_HOST=server_ip
KYODO_PROXY_PORT=port
KYODO_PROXY_USERNAME=username
KYODO_PROXY_PASSWORD=password
```

Файл `.env` исключён из Git. Не публикуйте его и не вставляйте настоящий
пароль в исходный код. После изменения `.env` перезапустите `main.py` и
`web_app.py`.
